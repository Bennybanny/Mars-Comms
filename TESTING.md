Version 0.2.4 centralizes removal of peer-owned presence, talk, listen and signaling references before transport teardown. The previous implementation spread cleanup across close callbacks, snapshot pruning and a five-second boolean heartbeat loop; a silent peer could remain visible for five to ten seconds, and server rejection initially called close without immediately removing/broadcasting runtime state. Both targeted regression tests fail against the previous source and pass with the fix. Transport pongs alone also left no deadline for a frozen application's talk state. The existing client watchdog now sends an application heartbeat every two seconds; the same server registry/deadline reconciliation checks both transport and application liveness. The operator's exact physical Wi-Fi sequence still needs repeating with this build.

The new `tests/disconnect.test.ts` contains 13 cases: clean PTT, single-group latch, multi-group latch, a real WebSocket with automatic pong disabled but application heartbeats still arriving, a page-silence simulation with transport pongs still arriving, stalled close handshake plus late state/signal/pong frames, user disable/delete, logout, session expiry, membership removal and group disable/delete. The dead-peer case also verifies that a second peer using the same user AND session remains connected and transmitting, and a returning peer has a new ID with empty talk/listen. Heartbeats use production timing: one-second checks and five-second deadlines, normally five to six seconds to remove a silent peer. Tests check corrected snapshots received by a separate observer, not only internal data structures. The browser test additionally checks the observer clears its talker after disconnect, reconnect leaves latch off, and deliberately restarting transmission produces increasing received RTP audio energy.

The operator reports successful real PC/iPhone microphone, PTT and bidirectional audio testing before this change. Automated checks here use synthetic browser audio; the updated physical disconnect behavior and eight-client production load have not been verified here.
