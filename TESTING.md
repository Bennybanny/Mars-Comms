# Verification record

Version 0.2.3 detects suspended/interrupted audio contexts and muted/ended microphone tracks, clears local and signaled transmission, and exposes Resume audio instead of showing a falsely enabled microphone. Resume starts context/playback recovery inside the button gesture before awaiting microphone permissions. The browser regression suspends an active sender's real AudioContext, checks remote talk is cleared and PTT disabled, then verifies Resume leaves latch off and a new deliberate latch produces increasing received RTP audio energy. All three browser tests passed. This simulates an audio interruption in Chromium; it does not prove the reported certificate-download sequence on physical iOS hardware.

Version 0.2.2 addresses a portable-only shutdown hang reproduced by starting the actual self-extracting EXE normally and sending Windows' native window-close signal. The old build removed its window but left the main process/wrapper alive, blocking later launches. The new Windows `test:portable` smoke test deliberately uses no debugger: it checks a visible native window, clean app/wrapper exit on close and a complete subsequent launch/close. Separate extraction folders prevent repeated portable launches from interfering with the existing process's files. Normal shutdown stops services first, then explicitly exits the Electron GUI process; an eight-second failure deadline prevents an indefinite orphan. Launcher diagnostics are saved to `logs/launcher.log` inside the application-data directory.

Version 0.2.1 fixes a blank intercom page caused by setup-route CSP middleware overriding the React page/asset policy. The new packaged regression test first reproduced the failure in 0.2.0, then verifies the actual HTTPS login page, loaded dark stylesheet, browser login, intercom rendering and WebSocket connection. Service tests independently check that HTML/JS/CSS retain the application policy while HTTPS/HTTP setup endpoints retain their stricter policy. The earlier 0.2.0 native test exercised the login API and browser-open URL but did not render the intercom page; this gap is now covered.

Verified locally on Windows with Node.js 24.19.0, Chromium 156 (Playwright), Electron 44.7.2 and electron-builder 26.15.3.

- `npm run build`: TypeScript validation, production React bundle, Electron main/preload/renderer and generated application icon.
- `npm test`: 14 tests covering the original password/auth/session/CRUD/permission/persistence/WSS logic plus IPv4 filtering, packaged/XDG data paths, saved NIC loss, persistent CA and leaf signing, SANs, key matching, CA reuse, leaf renewal, IP mismatch, validity/expiry states, public-only export, damaged-key recovery without automatic CA replacement, setup-route allowlisting, private-key path denial, real HTTPS start/stop, duplicate start prevention, mDNS failure fallback, failed-bind rollback and non-destructive legacy database import including WAL data.
- `npm run test:browser`: 3 tests passed. Three isolated browser clients use synthetic microphone input and real peer connections. Incoming RTP reports nonzero audio energy; administrator gain zero stops energy growth and restoring gain restores audio. Listen toggle and per-group volume affect audio playback; Camera latch survives temporary Tech PTT, both recipient groups see the active sender, and offline/reconnect clears latch. Admin UI creates groups/users and edits mic gain. Normal-user administration returns 403. Layouts checked at 1920×1080, 1366×768, 390×844 and 412×915 without horizontal overflow.
- `npm run test:desktop`: actual native Electron window. Certificate generation, native-dialog export operation (dialog selection substituted by the test), trusted HTTPS login, limited HTTP certificate download, QR image/address, default-browser launch operation (shell launch substituted), Start/Stop, CA reuse, window-close shutdown and remembered selection after reopening. Renderer Node/require access is absent; no page errors were observed. Screenshots inspected for the launcher and QR dialog.
- `npm run package:win`: Windows x64 NSIS installer and portable EXE generated with application icon/metadata and bundled runtime/frontend/backend. Builds are unsigned. ASAR inspection found no application data, certificate directories or raw backend/test sources included.
- `npm run test:packaged`: the same full native test runs against `release/win-unpacked/Mars Comms.exe` with `app.isPackaged === true`, independently of a development Electron launch. Test data lives in an isolated temporary folder. This exercises the real packaged backend, CA signing, SQLite and packaged asset paths. The installer has not been installed into the user's OS as part of automation.
- Dependency audit: no reported production dependency vulnerabilities. The development-only electron-builder dependency chain currently reports eight moderate audit entries propagated from the sprintf-js precision denial-of-service advisory; upstream audit reports no compatible automatic fix. These dependencies are not packaged in the application.

Not verified here: physical microphones/headsets, real LAN UDP across devices, actual acoustic quality/latency, mobile Safari/Android behavior, mobile CA installation, hardware speaker selection, an eight-user production load, OS trust-store installation, macOS/Linux native execution, signing/notarization or actual cross-device mDNS resolution. CI is configured for all three OSes and Windows artifacts; configuration alone is not evidence remote runners passed. Synthetic browser audio is not proof of real headset quality.
